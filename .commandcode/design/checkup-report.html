// WHAT'S WORKING

Composition

Rail / main / flow three-zone grid matches the Monitor + Operate work pattern. The user can see system state, live channels, and event history without tab-switching.

Color system

OKLCH warm-graphite base (not the usual cold slate). Signal vocabulary is small: amber armed, warm red recording, green done, blue info. Each role has one job.

Type system

IBM Plex Sans KR for prose, JetBrains Mono for all measurements, IDs, paths, and timestamps. Mono carries the data; sans carries the meaning.

Motion

Custom ease-out (cubic-bezier(0.16, 1, 0.3, 1)), staggered card entrance, blinking REC dots at desynced cadences (1.2s / 1.6s / 2.4s), reduced-motion fully respected.

Empty states

Every container (channels grid, ledger, event stream) has an authored empty state with a "what goes here" headline and a "next action" hint. None of them say "no data".

Brand mark

Custom radial-gradient mark with an amber inner frame and a blinking red dot. Reads as "recording booth" without leaning on the generic video-camera icon.

// PRIORITY ISSUES
P0 · CONTRACT

is_live missing from /api/channels

app/templates/index.html's renderChannels() branches on ch.is_live to render the LIVE pill. app/main.py:391-422 never emits that key. The pill will only ever show IDLE or REC. The backend already calls chzzk_client.is_live() in the monitor loop at main.py:177 but does not surface the result.

FIX: add is_live to the channel dict in api_list_channels; back it with a cached field updated by the monitor loop to avoid per-refresh chzzk calls. Then re-run /design checkup.
P1 · INTERACTION

editChannel uses three stacked prompt() calls

The edit flow calls prompt() twice and confirm() once in sequence, breaking the modal system the rest of the app uses. Keyboard tab order is interrupted, and the dialogs cannot match the surface styling.

FIX: build a single "Edit Channel" modal reusing the Add Channel shell, pre-fill with current values, save on one confirm. Run /design interaction channels to spec the form.
P1 · TIMEZONE

started_at is naive UTC, UI displays without timezone

app/main.py:264 stores datetime.utcnow() (naive, UTC by convention). The UI formats as 2026-06-11 14:23 with no zone indicator. Korean users running a local recording tool will read this as local time and misinterpret logs. Korea is UTC+9; the gap matters.

FIX: store aware datetimes (datetime.now(timezone.utc)), format as KST in the renderer, and apply the same convention to the event stream. /design surface will spec the time presentation system.
P2 · SCALING

No cached is_live on the channel record

Once is_live is added to the response, every 6s refresh will trigger one chzzk call per channel. With several registered channels this scales poorly.

FIX: persist last_is_live and last_is_live_at on the channel row; update from the monitor; emit in the API.
P2 · BRITTLENESS

Event stream dedup uses a 3-line signature

loadLogs() builds sig = logs.slice(0, 3).map(...).join("|") and returns early if unchanged. Safe today because older log rows are immutable, but a brittle pattern if log content ever becomes mutable.

FIX: compare the full payload or use a server-emitted monotonic id. Not urgent.
